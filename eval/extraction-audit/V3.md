# Extraction audit: evaluator v3

`AUDIT.md` describes the protocol as it was frozen. Its evaluator (v2, `src/eval/extractionAudit.ts`) and the archived v1 source still reproduce every committed report, and `npm run audit:score` checks that. Evaluator v3 (`src/eval/extractionAuditV3.ts`) is for the next complete run.

## Why v3

v2 asked the model for zero-based character offsets and gave credit only when they matched exactly. Language models are poor at counting characters. On the saved partial run (`local-20261101-corrected`, 23 of 42 requests):

- 93 of 182 predicted facts had the right task and value but wrong offsets.
- Line c10 had all five values right and every span one character off, and scored 0 of 5.

## What v3 does

- **Facts and evidence are scored separately.** A fact is found when its task and value match the gold. Its evidence is supported when it covers the same text as the gold evidence, at any occurrence.
- **Evidence can be quoted.** The v3 prompt (`prompt-v3.txt`, `schema-v3.json`) asks for exact quotes, and the harness finds them in the input. Character spans are still accepted.
- **Comparisons are structural.** Span key order, extra keys, span order and the order of multiplication operands do not change the score.
- **Duplicates.** A repeated fact costs one duplicate and is not deleted. A reply with a duplicate is not exact.
- **Abstention.** Abstaining is not a fact. "No active instruction", or an empty list, on a line with no gold facts is correct. A failed request, an empty reply or an unreadable entity is never a correct abstention.
- **Failure labels.** Engine errors come first, and a failed request never counts as exact. A missing dose is not called a wrong dose.
- **Malformed entities and derivations** are rejected one by one, so a bad entity no longer crashes the report. A malformed derivation leaves its fact found but not supported.
- **Derivations are checked.** A gold derivation must compute to its value.

## Running it

```bash
npm run audit:infer -- --out eval/extraction-audit/local-NEW-ID --evaluator v3
```

This needs a local Ollama with the models in `eval/sig-extraction/models.json`. The runner refuses an `OLLAMA_HOST` that is not this machine.

## Labels v1 and v2

Labels v1 is `public.json`, the AI-drafted labels the frozen protocol uses. It stays byte for byte as evidence.

Labels v2 is `public-v2.json`: v1 plus 19 corrections in 18 public excerpts, listed in `public-v2-changes.json`.
- Claude proposed them in `docs/KEVIN-REVIEW.md`, and Kevin Madden, PharmD, accepted all 19 as a batch on 3 November 2026.
- No pharmacist has checked them one by one yet, so v2 is still a draft.
- `src/eval/auditLabels.test.ts` derives v2 from v1 again, byte for byte, and checks its SHA-256 (`6942d6e0c4f449fe006984243e9292b244327ffa04b0e47cca49435da46a8a1d`).
- The challenge lines are unchanged.

Evaluator v3 scores new runs against labels v2. The frozen v2 protocol keeps labels v1.

## Re-reading the saved partial run

The 23 saved replies, scored against both label versions (`src/eval/auditLabels.test.ts`):

| Evaluator | Measure | Labels v1 | Labels v2 |
|---|---|---|---|
| v3 | Gold facts found by value, all 23 lines | 92 of 134 | 99 of 129 |
| v3 | Gold facts supported by evidence, all 23 lines | 7 of 134 | 8 of 129 |
| v3 | Gold facts found, the 18 public excerpts | 78 of 119 | 85 of 114 |
| v3 | Predicted facts not in the gold, all 23 lines | 76 | 69 |
| v2 (frozen) | Predicted facts supported, exact offsets | 6 of 182 | 7 of 182 |

The run is incomplete and both label versions are drafts, so none of this is a result. It is development data. It shows how much of the v2 score was offset counting, and how much the label fixes move the count.
